Lane: E1
What is odd (2–4 sentences): The 2012 trial report says seven half-squares in the northwest ("Area B, not included in this report") exposed "remains dating to the Early Islamic period". The 2014 salvage report, under the same permit and the same map ref., says the opposite: "The complexes from the earlier periods … were not in use during Islamic period", with only "several body sherds", mostly at the northwest end (L152). The Hebrew text has the same contradiction. The 2012 trial had already found high-temperature slag that it could not assign to ceramic or metal working (Sq. M3, L106). Metallurgy specialists are credited in both reports (R. Vinitzky 2012; Y. Kupershmidt 2014), but neither report gives a metallurgical result.

Title (one line): All 2,215 HA-ESI DOIs in the corpus carry "116.2004" whatever the report's real volume and year, and their Crossref records list "Israel Antiquities Authority" as an extra first author
Lane: E1
What is odd (2–4 sentences): The DOIs the IAA minted for HA-ESI look like volume.year.id, but the volume.year segment is the same for all 2,215 distinct DOIs cited across the 9,335 text files of the corpus: `10.69704/jhaesi.116.2004.<id>`. The id can be matched to `reports_metadata.csv` for 2,212 of them. In 2,185 of those the report is in fact in a later volume (e.g. id 2124 is HA 124, 2012); the other 27 really are HA 116 reports. A "corrected" DOI built from the real volume (`10.69704/jhaesi.124.2012.2124`) returns 404 at doi.org. The Crossref records for 8 of 8 sampled DOIs (2124, 13677, 448, 25883, 1289, 2185, 25923, 27707; checked 6 Nov 2026) have `volume: null`, owner prefix `10.70967` (not the DOI's 10.69704), and "Israel Antiquities Authority" entered as an author. The IAA entry has `sequence: first` beside the real first author, and is repeated before every co-author (25883 has six such entries).
Evidence (exact sources: file path / page / figure / frame / coordinates): bucket `hadashot/derived/hadtext_pdftotext.tgz` (extracted copy used: `/home/claude/swarm/scratch/B1b/txt/hadtext/`), regex `10\.69704/jhaesi\.(\d+)\.(\d+)\.(\d+)` → 2,215 distinct DOIs, all `116.2004`; matched against `reports_metadata.csv`. Example in a drawn report: Mamalya, HA 133 id 25923, cites "Paran and Sonntag 2012, HA 124" with DOI `…116.2004.2124-he`. Crossref API https://api.crossref.org/works/10.69704/jhaesi.116.2004.2124 and the 7 others above. doi.org redirects: `…2124` → `Report_Detail_Eng.aspx?id=2124`; `…2124-he` → `report_detail.aspx?id=2124`; `…124.2012.2124` → 404.
Literature check (queries run, result, tag): web search for "10.69704/jhaesi.116.2004" returned nothing relevant. Repo: the only mention is `research/regional/haesi_features/README.md` l.116 ("DOIs of the form 10.69704/jhaesi.* redirect there"). **NEW TO THE LITERATURE** (a metadata quirk, not archaeology).
Why it might matter: Reference managers and bibliometric tools that read DOI metadata will import every HA report with no volume, the IAA as co-author, and (if they parse the DOI string) a false 2004 date. Any project table that guesses volume or year from HA DOIs would be wrong for 99% of reports. The fix for users is to key on the id and take volume and date from `reports_metadata.csv`.
How to confirm or kill it (with data in hand, or what is missing): Run the regex and the Crossref call (5 minutes). It is killed only if the IAA documents "116.2004" as a fixed journal-level token, which would make it a design choice and not an error. The author duplication would remain either way.
Confidence: high
Touches the Copper Scroll? no
